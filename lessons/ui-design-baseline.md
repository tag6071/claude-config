[rule:ui-design] Clean, minimal, best-in-class UI/UX. Empty / error / loading states are DESIGNED, not afterthoughts. EVERY UI ships three color modes: auto (default) / light / dark — all built with equal care, a discoverable toggle, and the choice persists. Test at 375px and 1280px.

[rule:ui-ergonomics] Fewest clicks/taps that does the job. Never hide a one-click action behind two or three; never expand a single step into a wizard it doesn't need. Pre-fill sensible defaults, make the primary action obvious, auto-advance where it saves a click, keep keyboard + focus order intentional. Reducing what the user has to type or tap is a feature, not a nicety.

[rule:ui-adopt-dont-reinvent] Adopt a battle-tested base, tweak tokens for branding — never reinvent solved primitives. Distinctiveness comes from design TOKENS (palette, type, spacing, motion) applied to solved components, NOT from bespoke widgets or hand-stitched CSS. So: interactive primitives (dialog, select, combobox, popover, dropdown, tooltip, tabs) MUST be the stack's shadcn/Radix components — a hand-rolled `<div role=dialog>` or native `<select>` loses focus-trap, aria-modal, and Escape/restore-focus that were solved years ago. THIS GENERALIZES BEYOND shadcn primitives to EVERY solved problem (per [[build-vs-adopt]]): data grids → TanStack Table, date/time → date-fns/Temporal, charts → Recharts/visx, file upload, virtualization → TanStack Virtual, command menu → cmdk, drag-drop → dnd-kit, rich text, i18n, etc. Adopt the mature library; build ONLY the differentiated ~20% as thin documented glue over it (e.g. the scaffold's `AppForm` is ~30 lines over react-hook-form+zod+shadcn — NOT a new form lib). The lint gates only mechanically catch the few regex-detectable cases (native select/modal/form, CSS-in-JS); the rest is on you + review — if you're about to hand-write something non-trivial, search OSS first. Styling is Tailwind utilities + tokens — NEVER CSS-in-JS (`<style>{…}`/`style={{}}`) or hand-written `.css` beyond the one global token sheet. Exactly ONE token source + one theme mechanism — never grow a second (it goes stale and they drift). "Badass and distinctive" is achieved 100% this way — bespoke CSS is not required for it and is not an excuse to abandon the stack.

[rule:ui-scale] Same role → same scale token. Type & spacing come from ONE named scale whose VALUES you choose deliberately per project in tailwind.config — not Tailwind's defaults left unchanged (shipping defaults IS the generic-web-slop look). "Custom values" constrains only WHERE the numbers come from (you), never WHAT aesthetic you build — any style is fair game. Set a base unit + rhythm (your 8/12/16/20), a type ramp (your ratio + matched line-height + letter-spacing), optionally SEMANTIC keys (text-label/meta/body/title, gap-section) — the "named type/rhythm scale" done Tailwind-native, no second --fs-* system. Then use only those tokens (text-title, p-4, gap-section) — NEVER arbitrary values (text-[13px], p-[13px], gap-[7px]) or bare font-size/padding px in CSS. Distinctiveness lives in the scale's VALUES; consistency lives in everyone using the same named tokens — NOT in tension. Fixed width/height arbitraries (w-[420px]) are fine. Vertical rhythm is owned by `gap`/`space-y` on a stacked container, NOT each component's own margins — reset child block margins so spacing isn't double-counted. Choosing the ramp: see the frontend-design skill. Refactoring an inconsistent UI to this WITHOUT changing the look = the `/ui-conform` skill (pixel-identical, screenshot-verified): audit de-facto usage → tokenize with ZERO pixel change first (pure rename, checkpoint) → fix one exemplar → sweep the rest → the lint gate keeps it from regressing. (Want a NEW look instead → `/ui-overhaul`, which is destructive.)

[rule:ui-stable-layout] Nothing moves when you click. A click changes content INSIDE fixed boxes; boxes never move, resize, or reflow the page. Build it into the structure, not as fixes: a sticky fixed-height header; fixed-height regions for anything that changes (status lines, verdicts, step titles; reserve the space when empty, `invisible` not conditional render; clamp text to a fixed line count); media sized to its box, not its content (a 1-item list and an 8-item list are the same size); notices float as overlays instead of pushing content; `scrollbar-gutter: stable`; selected vs unselected states never change size or weight (`border-transparent`, same font weight); grid columns `minmax(0,1fr)` (`grid-cols-1`) so nowrap content can never widen the page; no auto-scrolling on mount; arrow keys used by the app `preventDefault`. Offer a zen/full-screen mode for focus apps. Lock it with an automated test that records element boxes, clicks through every state, and fails on any pixel of movement, plus a "page never wider than the window" check at 375/768/1024/1280.
